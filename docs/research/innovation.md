# What is actually new here

Stated carefully, because "innovative" is easy to write and hard to support. Some
of what follows is novel in this problem space; some is ordinary engineering done
properly. Both are listed, labelled.

## 1. Attribution detection built to survive disguise (novel here)

The obvious implementation is a case-insensitive substring match. The interesting
part of this problem is that attribution is **visible to a human and invisible to
a matcher**, or the reverse.

The approach taken:

- **Rules are data, not code** (`rules/*.yaml`): identities, domains, bots and
  patterns, with a documented evidence model.
- **Exact matching after normalisation**, never substring or fuzzy: `Claude` never
  matches `Claudette` or `Claude Dupont`.
- **Normalisation for comparison only**: NFKC, case folding, whitespace
  collapsing, removal of every Unicode default-ignorable code point, and a small,
  explicit map of Cyrillic and Greek look-alikes. Evidence shown to the user is
  always the original text.
- **A trailer parser with no regular expressions**, linear in message size and
  bounded in trailer count, that records *why* a line was odd (missing separator,
  nonstandard key, leading characters) instead of silently ignoring it.
- **Evidence strength is modelled**: an exact vendor e-mail or bot login is strong;
  a bare alias is medium; a vendor domain alone is never sufficient. A commit by a
  human employee of an AI vendor is not a violation.

Three bypasses in this layer were found by the project's own dataset and fuzzers,
each in a category (symbols, Unicode alphanumerics, default-ignorable characters)
that a substring matcher has no answer to at all.

## 2. Measuring a security tool against labels it cannot influence (method)

The dataset states the decision the policy **must** reach, derived from documented
semantics and security requirements, never from the implementation's output. A
mismatch is a failure, not a labelling problem. Combined with:

- dataset versions that only ever add cases, each rebuilding to a fixed
  fingerprint;
- results that are immutable, so failing runs stay published;
- the discipline of recording the failing run **before** the fix exists.

The result is thirteen detection runs, four of which failed, published together.
That is unusual for a personal project and is the part most worth borrowing.

## 3. Experiments that record outcomes, including failures (method)

Security tests here do not only assert; they record what was observed and classify
the outcome as `prevented`, `detected`, `bypassed` or `not_applicable`. Seven local
bypasses are recorded as **succeeding** against the local layer. The evidence file
is generated by the test run, so it cannot drift from reality.

Two experiments initially passed for the wrong reason and were fixed - the
method's value is precisely that this was discoverable.

## 4. Enforcement that a contributor cannot weaken (engineering)

Standard practice elsewhere, rarely implemented completely:

- the policy is read from the **base** commit, so a pull request cannot relax the
  rules that judge it;
- rules come from the installed package, never the repository;
- the workflow installs CommitGuard from a trusted commit via `git worktree`, so
  the scanner itself is not the contributor's;
- a **mandatory policy** applied after all layers can only make enforcement
  stricter - proven as a property over generated configurations, not as examples.

## 5. Failing closed, everywhere, and saying so (engineering)

A detector that crashes blocks. An unparseable configuration is exit 2, not an
implicit allow. A finding with no policy blocks. GitHub unreachable, permissions
revoked or the database down all produce `error`, never `success`. The dashboard
has explicit states (`ERROR`, `STALE`, `NOT CONFIGURED`, `DISCONNECTED`) instead
of one green tick, and `doctor` reports `NOT CONFIGURED` rather than implying that
an unconfigured integration is protecting anything.

## 6. Refusing to overstate (method)

Every report labels each line **Measured**, **Tested**, **Observed**, **Expected**
or **Not tested**, and prints *Not tested* rather than omitting a section. The
documentation states that local hooks are bypassable, that branch protection is
modelled, that the author wrote both the tool and its evaluation, and that no
external evaluation or production deployment has happened.

## What is *not* new

- The idea of scanning commit metadata for AI attribution.
- Git hooks, GitHub Checks and webhook services.
- Precision, recall and property-based testing as techniques.

The contribution is the combination: a defence-in-depth enforcement design, an
adversarial dataset with immutable results, and a published record of its own
failures.
