# Compliance reporting

Security teams need evidence they can hand to auditors: which repositories are
protected, which violations are open, which exceptions exist and who approved
them, and how policy changed over time. CommitGuard exports that evidence as
point-in-time reports.

> **What these reports are not.** A CommitGuard report describes CommitGuard
> policy enforcement at the time it was generated. It is **not** a SOC 2,
> ISO 27001 or any other certification or attestation, and does not claim that
> an organization meets any framework. Every report carries this notice.

## Reports

`GET /api/v1/organizations/{id}/reports/{kind}?format=json|csv` (`security:read`)

| Kind | Rows | Summary |
|---|---|---|
| `compliance` | one row per repository: posture and reasons, protection, connection, mode, onboarding, policy state, organization policy version, open and critical violations, active exceptions, drift, last scan | posture, repositories, protected, at risk, unprotected, critical findings, active exceptions, compliance fraction |
| `coverage` | same rows as `compliance` (a coverage view of the same snapshot) | same |
| `violations` | open and closed violations grouped by rule, severity, action, status and repository | groups, `truncated` |
| `exceptions` | every exception: rule, scope, action, status, reason, requested by, approved by, expiry, permanent | exceptions, `truncated` |
| `policy_changes` | organization and scoped policy publications, rollbacks, emergency publications, approvals, rejections, settings and rule changes, with actor and details (also needs `audit:read`) | changes, `truncated` |
| `installations` | installation state and synchronisation health | installations |

Example summary of a compliance report:

```json
{
  "report": "compliance",
  "organization": "octo-org",
  "generated_at": "2026-09-17T10:04:11+00:00",
  "generated_by": "ada",
  "notice": "Policy compliance report generated by CommitGuard. It describes CommitGuard policy enforcement at the time shown; it is not a SOC 2, ISO 27001 or any other certification or attestation.",
  "summary": {
    "posture": "at_risk",
    "repositories": 100,
    "protected": 92,
    "at_risk": 5,
    "unprotected": 3,
    "critical_findings": 4,
    "active_exceptions": 7,
    "compliance": "91 of 98 required repositories satisfy all mandatory controls"
  },
  "rows": ["..."]
}
```

The compliance fraction and posture rules are defined in
[security-posture.md](security-posture.md).

## Guarantees

* **Point in time.** A report is computed when it is requested and says when
  (`generated_at`) and by whom. It is not regenerated behind the reader's back.
* **Scoped to the requester.** Rows include only repositories the requester can
  see on GitHub (Phase 6 access scope); another organization's data never
  appears; `policy_changes` additionally needs `audit:read` (404 otherwise, like
  any resource the caller may not know about).
* **Bounded.** At most 10,000 rows per report. A larger result is cut, and the
  summary says `"truncated": true`; it never looks complete when it is not.
* **Audited.** Every export records `report_exported` with the kind, format and
  row count.
* **No secrets.** Reports contain the same redacted evidence as the dashboard;
  tokens, webhook secrets and session data are never included.
* **Safe CSV.** The first lines are comments with the notice, organization and
  time. Cells starting with `=`, `+`, `-`, `@`, tab or carriage return are
  prefixed with `'` so a spreadsheet does not execute them as formulas (CSV
  injection through repository names, reasons or commit metadata).
* **Downloaded, not rendered.** Responses carry `Content-Disposition: attachment`
  with a file name such as `commitguard-octo-org-compliance-20260917T100411Z.csv`.

## Evidence behind the numbers

Reports summarize records that stay available individually:

| Question | Where |
|---|---|
| Which policy applied to this scan? | the scan's recorded governance versions and per-rule provenance |
| Who changed the policy, and who approved it? | audit log (`policy_published`, `policy_approved`, `policy_emergency_published`), filterable by `policy` |
| Why was this rule not blocked? | the scan's provenance: exception ID, scope, approver, expiry |
| When did an exception expire? | audit log (`exception_expired`), filterable by `exception` |
| What did a rule decide over time? | audit log and violations, filterable by `rule` |

The audit log is append-only: a database trigger refuses updates. It is readable
and filterable in the dashboard by members with `audit:read`
([dashboard.md](dashboard.md)).

## Retention decides how far back evidence goes

| Record | Kept |
|---|---|
| policy versions (organization, group, repository), drafts, approvals, exceptions, rollouts, organization rule versions, current organization settings | permanently (versions are immutable; exceptions cannot be deleted). Earlier settings are recorded only in audit events |
| audit events, finished scans with their recorded provenance, resolved violations | `COMMITGUARD_APP_RETENTION_DAYS` (**default 30 days**) |
| finished simulations, bulk operations, scheduled scan runs | `COMMITGUARD_APP_RETENTION_DAYS` |
| daily security metric snapshots | permanently (one small row per organization per day) |
| notification events | `COMMITGUARD_NOTIFICATION_RETENTION_DAYS` (default 90 days) |

The `policy_changes` report and the audit log only reach back as far as audit
retention. If auditors expect a year of evidence, set
`COMMITGUARD_APP_RETENTION_DAYS` accordingly (for example `400`) **before** that
year starts, or export reports on a regular schedule and store them yourself.
Evidence already purged cannot be recreated.

## Limits

* Reports reflect what CommitGuard recorded. Commits merged while CommitGuard
  was not installed, suspended or not required by branch protection were not
  checked, and the posture rules say so rather than counting them as compliant.
* Trends of protection, exceptions and drift exist only from the first daily
  snapshot onwards.
* There is no scheduled report delivery; reports are generated on request.
