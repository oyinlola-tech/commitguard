# Audit log

Audit events record security-relevant actions by users, GitHub and CommitGuard
itself. Every mutation that changes security state writes its audit event in the
same database transaction. The API is read-only: there is no endpoint that
creates, changes or deletes audit events.

Source: `list_audit` and `get_audit_event` in
`src/commitguard/controlplane/queries.py`; event types in
`src/commitguard/audit/models.py`.

| Method and path | Permission | Rate-limit category |
|---|---|---|
| [`GET /api/v1/audit`](#get-apiv1audit) | `audit:read` | `read` |
| [`GET /api/v1/audit/{event_id}`](#get-apiv1auditevent_id) | `audit:read` | `read` |

`audit:read` is held by security managers, admins and owners, not by viewers.

An event is visible when all of these hold:

- its organization grants `audit:read`;
- its installation, if any, is one GitHub listed for the session;
- its repository, if any, is one GitHub listed for the session.

## AuditEventView

| Field | Type | Description |
|---|---|---|
| `id` | string | 32 hexadecimal characters |
| `type` | string | An event type, see below |
| `occurred_at` | string (date-time) | |
| `actor` | object | `{type, id, login}`; `type` is `system`, `github` or `user` |
| `organization_id` | integer or null | |
| `installation_id` | integer or null | |
| `repository` | object or null | `{id, installation_id, full_name}` |
| `head_sha` | string or null | |
| `action` | string or null | `allow`, `warn` or `block` |
| `summary` | string | One line, generated by the server |
| `data` | object | Event details; values are strings, integers, booleans or null |
| `scan` | string or null | Related scan execution ID |

## GET /api/v1/audit

| Query parameter | Values | Default |
|---|---|---|
| `organization` | positive integer | |
| `repository` | positive integer | |
| `type` | an event type | |
| `actor` | part of the actor login, up to 100 characters. Validation errors report `field` `q`. | |
| `from`, `to` | ISO 8601 date or date-time, compared with `occurred_at`; `from` inclusive, `to` exclusive | |
| `rule` | `ai_coauthor`, `ai_identity`, `ai_trailer`, `malformed_trailer`, `bot_identity` | |
| `exception` | exception ID (32 hexadecimal characters) | |
| `policy` | `organization` (organization policy, emergency publication and settings events), or a draft, group or rollout ID (32 hexadecimal characters) | |
| `sort` | `newest`, `oldest` | `newest` |
| `cursor`, `limit` | See [pagination.md](pagination.md); keyset cursor | `limit` 25 |

Response `200`. `data` is an array of `AuditEventView`; `meta` is
`{next_cursor, limit}`.

Errors: `400 VALIDATION_ERROR`; `403 FORBIDDEN` when the caller has
`audit:read` in no organization; `404 NOT_FOUND` when `organization` names an
organization without `audit:read`.

```bash
curl -s 'https://commitguard.example.com/api/v1/audit?type=organization_policy_changed&limit=10' \
  -H 'Cookie: __Host-commitguard_session=<session-token>'
```

## GET /api/v1/audit/{event_id}

Response `200`. `data` is an `AuditEventView`.

Errors: `404 NOT_FOUND`.

## Event types

GitHub and scans:

- `installation_created`, `installation_removed`, `installation_suspended`,
  `installation_unsuspended`, `installation_permissions_updated`
- `repositories_added`, `repositories_removed`, `repositories_synced`
- `webhook_rejected`, `authorization_denied`, `pull_request_merged`
- `scan_queued`, `scan_requested`, `scan_started`, `scan_retry_scheduled`,
  `repository_scanned`, `scan_passed`, `scan_failed`, `scan_error`,
  `scan_cancelled`
- `check_rerun_requested`, `check_rerun_rejected`
- `merge_group_created`, `merge_group_passed`, `merge_group_blocked`,
  `merge_group_scan_failed`, `merge_group_destroyed`
- `policy_violation`, `policy_modification`, `configuration_error`,
  `enforcement_status_checked`

Users and members:

- `user_signed_in`, `user_signed_out`, `session_revoked`
- `member_role_granted`, `member_role_changed`, `member_removed`

Violations:

- `violation_opened`, `violation_reopened`, `violation_resolved`
- `violation_acknowledged`, `violation_acknowledgement_removed`

Repositories and groups:

- `repository_monitoring_disabled`, `repository_monitoring_enabled`
- `repository_discovered`, `repository_onboarded`, `repository_excluded`,
  `repository_mode_changed`, `repository_archived`, `repository_sync_failed`
- `repository_group_created`, `repository_group_updated`,
  `repository_group_archived`, `repository_group_members_added`,
  `repository_group_members_removed`

Policies:

- `organization_policy_changed`, `organization_policy_rolled_back`
- `policy_draft_created`, `policy_draft_updated`, `policy_draft_cancelled`
- `policy_approval_requested`, `policy_approved`, `policy_rejected`
- `policy_published`, `policy_emergency_published`, `policy_rolled_back`,
  `policy_simulated`
- `policy_rollout_started`, `policy_rollout_advanced`, `policy_rollout_paused`,
  `policy_rollout_resumed`, `policy_rollout_completed`,
  `policy_rollout_rolled_back`, `policy_propagation_failed`

Exceptions and organization rules:

- `exception_requested`, `exception_approved`, `exception_rejected`,
  `exception_cancelled`, `exception_revoked`, `exception_expired`
- `organization_rules_changed`

Notifications:

- `notification_created`, `notification_delivered`,
  `notification_delivery_failed`, `notification_read`
- `notification_settings_changed`, `notification_preferences_changed`
- `notification_webhook_added`, `notification_webhook_removed`

Organization operations:

- `organization_settings_changed`
- `scan_schedule_created`, `scan_schedule_changed`, `scan_schedule_disabled`,
  `scheduled_scans_queued`
- `bulk_operation_requested`, `bulk_operation_finished`,
  `bulk_operation_cancelled`
- `security_event_acknowledged`, `report_exported`
